# 金匱跨經典知識模型

## 來源與範圍

本輪只覆核 V1 `renji/jingui/01–06`、既有傷寒方藥與《金匱要略》古典原文，建立 5 篇導讀，不重製全文、劑量、煎服法或完整方庫。專案材料可追溯為本站編輯整理與古典來源；沒有足夠資料把任何新增內容標為倪海廈逐字講授。

## 經典、病類與病證

《金匱要略》使用唯一 `classic:jingui-yaolue`。血痹、歷節、虛勞、肺系病、腹滿寒疝、痰飲、婦人病建立為 `condition`，表示疾病／章篇組織入口；15 個具體方證沿用 `syndrome`，並以 `belongs_to` 回到病類。方劑只連 syndrome，不直接連 condition。這項區分具有跨經典價值，故 Schema 由 1.3.0 升至 1.4.0；未新增欄位、relation type 或 source category。

## 方劑身份與跨經典重用

金匱受控範圍共有 15 張方。12 個新身份為黃耆桂枝五物湯、桂枝芍藥知母湯、小建中湯、麥門冬湯、葦莖湯、射干麻黃湯、大建中湯、當歸生薑羊肉湯、苓桂朮甘湯、桂枝茯苓丸、甘麥大棗湯、當歸芍藥散。桂枝湯、大承氣湯、小柴胡湯直接重用傷寒 canonical entity；沒有 `jingui:*` 方劑副本，也沒有第二個頁面或第二套組成邊。

每個重用方各有兩條 `appears_in`，分別連兩部經典；傷寒方證與金匱方證使用不同 `classically_associated_with` relation。相同 Formula ID 不代表所有關係共享所有來源。

## 關係級來源

現有 relation `sourceIds` 足以回答「哪一來源支持這一條關係」。例如桂枝湯→太陽中風只帶傷寒來源，桂枝湯→妊娠桂枝湯證只帶金匱來源；formula entity 可列出兩組來源，但 entity 合集不會回填或污染 relation。`appears_in`、`contains_herb`、`belongs_to` 同樣逐條保存證據。本輪不需 Claim entity 或新 relation type。

## 藥材重用與歧義

15 方共使用 34 味唯一藥材。桂枝、芍藥、生薑、大棗、甘草、麻黃、白朮、知母、附子、半夏、人參、粳米、細辛、蜀椒、乾薑、當歸等 16 味直接重用傷寒 identity；新增黃耆、防風、飴糖、麥門冬、葦莖、薏苡仁、桃仁、冬瓜仁、射干、紫菀、款冬花、五味子、羊肉、茯苓、牡丹皮、小麥、川芎、澤瀉 18 味。黃耆／黃芪、川芎／芎藭以繁簡或 alias 指向同一節點，不另建副本。所選組成未發現需要并存的來源衝突；若未來來源藥味不同，必須記錄衝突，不得覆寫 canonical composition。

## 醫療安全與延後項目

病類、病證、方證和組成都只是經典研讀結構，不是診斷或推薦引擎。公開頁不提供劑量、藥材替換、自行購藥、處方調整或急症主張。完整金匱語料、全文、方藥 bulk ingestion、炮製、藥性、歸經、禁忌及本草關係均延後；中間麵包屑可點擊性仍保留為全站 UX 清理項。

## 準備度結論

Formula 和 Herb 的 global identity、alias、組成、跨經典 membership 及 relation provenance 已通過受控樣本，可以作為下一輪本草 Schema 壓力測試的身份基礎。尚不應直接大量匯入本草，因藥性、炮製、部位、來源植物、同物異名與安全證據仍需專門模型和可審查匯入流程。人紀的共享身份骨架已可進入下一個受控領域，但不等於完整臨床知識模型已完成。
