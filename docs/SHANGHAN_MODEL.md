# 傷寒知識模型 V2.6A

## 範圍與來源

本輪只驗證「《傷寒論》→診斷六經→代表病證→代表方→藥材」能否穩定進入共同知識圖譜。內容基礎是 V1 `renji/shanghan/01–07` 與 `renji/bencao/05`；《傷寒論》古典身份列為 `classical`，本站課程整理列為 `editorial`，廣西中醫藥大學原文教學頁只作方名與藥味組成的 `reference`，結構轉換另列 `derived`。沒有足夠證據的內容不標為 `nihaixia`。

不收錄完整條文、完整方庫、劑量、煎服法、炮製、替代藥、禁忌判斷、個人診斷或自動推薦。網站呈現的是所研經典框架中的知識關聯，不是醫療指示。

## 六經與病證決策

太陽、陽明、少陽、太陰、少陰、厥陰建立為 `shanghan_channel`，ID 使用 `shanghan-channel:*`。針灸同名條目仍是 `meridian_level`／`meridian-level:*`，表示十二正經命名層級。兩者名稱相同但語意、類型和圖譜上下文不同，不建立 `same_as` 或自動推導關係。

代表呈現建立為 `syndrome`。每個病證恰有一條 `belongs_to` 指向診斷六經；陽明腑證的輕、中、重三個代表層次以 `part_of` 回到陽明腑證總類。`syndrome` 名稱保持廣義，可供未來《金匱要略》或方劑主治語境重用，但跨經典合併仍須逐筆判斷語意。

## 方劑、藥材與關係

`formula`、`herb` 已存在於 Schema 1.2.0，本輪開始實際使用。十一方各有唯一穩定 ID、繁簡名稱、來源、導讀和 `ingredientCount`；二十九味藥只建立一份共享身份。

- `contains_herb`：方劑 → 藥材，表示接受來源中的組成事實。52 條關係逐方核對，metadata 數量必須與 edge 數一致。
- `classically_associated_with`：方劑 → 病證，表示本站所研經典框架中的代表方證關聯。它刻意不用「適應症」「推薦」語言，也不由症狀自動觸發。
- `appears_in`：方劑 → 《傷寒論》，表示經典身份關聯。病證的古典／編輯來源主要由 `sourceIds` 表達，避免為圖譜密度重複加邊。

結構事實集中在 rows 與 relations；導讀、安全說明和條目描述保持 curated。此形態尚未建立生成管線，但可以在擴量時轉為 generated base + curated overlay。

## Schema 壓力測試

Schema 升至 1.3.0，新增兩個 entity enum 與一個 relation enum；沒有欄位或 source category 變更。摩擦點如下：

- 若以 `concept` 承載六經與病證，無法確定性驗證方證端點，也會放大與針灸同名條目的歧義，因此需要 `shanghan_channel`、`syndrome`。
- `classically_associated_with` 比既有 `related_formula` 精確，方向固定且公開標籤明確保留經典語境；後者繼續保留相容性，但本輪不用。
- 方劑劑量、炮製和角色不是目前 metadata 的成熟模型。本輪主動不放入；擴量前需獨立來源與結構提案。
- `syndrome` 足以作為《金匱要略》代表病證的起點，`formula`／`herb` 可直接重用；本草藥性、歸經、炮製與藥對關係仍需下一次 Schema 壓力測試。

結論：模型已適合繼續做更大的受控《傷寒論》批次，並為《金匱要略》共享方劑／藥材身份做好準備；尚不適合直接全量匯入。擴量前應建立可審查的方劑來源清單、組成衝突規則與類似針灸的 dry-run／report 流程。

## 確定性驗證

驗證器固定檢查 6 六經、12 病證、11 方、29 藥材、5 導讀和 52 條組成關係；逐方比較接受的藥味集合，檢查唯一 ID／slug、來源／課程／關係端點、唯一六經歸屬、唯一方證關聯、經典關係、重複 edge、同名六經身份隔離、藥材去重及不出現劑量／推薦 metadata。公開建置另檢查繁簡搜尋、內部 enum 隔離、醫療安全說明、兩幅結構圖、連結與移動端版面。
