# 內容匯入與引導研讀規範

這份規範供後續資料整理使用；目前凍結階段不擴充人紀、其他大型模組或六十四卦全量資料。

## 匯入順序

1. 先確認原始材料可追溯，建立或重用 source。若只有本站整理稿，分類為 `editorial`，不可推定為 `nihaixia`。
2. 為每個概念選定語言無關的 namespaced ID，另建 URL-safe slug。先查重，名稱相近不等於同一 entity。
3. 填寫繁體標籤、描述、別名與最少一筆來源；簡體欄位可同批加入，但不得用機器轉換結果覆蓋人工校對內容。
4. 只使用 V1 關係詞彙。每條關係需確認方向、兩端 entity 和證據來源；不確定時先不建立關係。
5. 將 entity 連到最適合的 `relatedLessonIds`，讓讀者能從條目回到完整上下文；不要只為增加連結數量而掛課程。
6. 執行 schema、搜尋索引、靜態建置與公開頁檢查。驗證通過後才可提交。

## 引導研讀設計

研讀路徑以「完整課程正文 → 條目解釋 → 有來源的相關關係 → 延伸課程」為基本循環。課程頁保留章節順序及前後篇；entity 頁以人可讀類型、屬性與關係呈現，並列出內容來源。關係連結是輔助理解，不取代正文，也不應製造原始材料沒有表達的結論。

首頁和搜尋使用讀者語言，不顯示 schema enum、內部 ID、開發階段或資料匯入狀態。醫療相關內容延續既有研讀用途與安全邊界，不因結構化而變成診療建議。

## 未來批次的入口條件

每個新批次開始前，先寫一份資料清單，列出範圍、來源、預計 entity 類型、關係類型與明確不包含的內容。少量代表資料通過完整驗證後再擴量。遇到 V1 無法準確表達的概念時停止匯入，提出 schema 版本提案，不在內容檔內臨時創造欄位或 enum。

六十四卦、人紀或其他大型模組都必須作為獨立批次評估；本次凍結不預先宣告其資料已就緒。

## 編輯檢查表

- 繁體標籤與描述完整；可選簡體欄位不會造成頁面或索引失敗。
- 公開頁不出現原始 enum、metadata 鍵、內部 ID 或開發狀態文字。
- 每個 entity 至少一筆來源；來源分類和可追溯程度一致。
- relation 方向正確、端點存在、展示名稱自然。
- 搜尋可以由標籤、別名和正文關鍵詞找到內容。
- 課程、條目、來源與延伸研讀連結皆可到達。
