# 本草／藥材知識模型

## 受控範圍

V2.7A 只驗證 24 味既有藥材：桂枝、芍藥、生薑、大棗、甘草、麻黃、黃耆、石膏、知母、柴胡、黃芩、半夏、人參、附子、乾薑、黃連、當歸、茯苓、白朮、川芎、五味子、麥門冬、大黃、芒硝。全部重用傷寒／金匱建立的 `herb:*`；新增 Herb 為 0。沒有匯入整部《神農本草經》，也沒有建立批次 ingestion pipeline。

## 身份邊界

Herb 表示傳統醫藥使用的藥材身份，不等同植物物種、化學物質或所有加工品。現有生薑與乾薑保留兩個藥材身份；本輪不建立兩者的植物來源或炮製推導。白朮、芍藥、桂枝等古今名物對應存在歷史摩擦時，只在來源足夠的層級建立關係，不宣稱完成植物分類。

## 藥性與藥味

藥性使用 5 個 `herb_nature`：寒、涼、平、溫、熱；微寒／小寒作為「涼」的顯示別名，大熱作為「熱」的別名。藥味使用 5 個 `herb_flavor`：酸、苦、甘、辛、鹹。一味藥可有多個 `has_flavor`，但 nature 與 flavor 永遠是不同類型與關係。

現存古典整理、本站課程與現代規範並不總一致。人參保留古典「小寒」與本站／現代「微溫」，大棗保留古典「平」與本站／現代「溫」，麥門冬保留整理本「平」與現代「微寒」。它們不是 entity metadata 的覆寫值，而是不同 `has_nature` 關係，各自保存 sourceIds。

## 歸經

`has_tropism` 從 Herb 指向既有 `organ:*`。這裡的 Organ 是中醫臟腑／系統研讀身份；它與 acupuncture Meridian 由既有 `corresponds_to` 相連。穴位 `belongs_to` 經脈與藥材 `has_tropism` 臟腑語意不同，因此不共用 relation。

本輪不建立 Herb → Meridian，也不建立 Herb → Element。需要五行時可沿 Herb → Organ → Element；需要針灸區域時可沿 Herb → Organ ← Meridian ← Acupoint。這些路徑只表示已存關係的可探索組合，不生成治療推薦。

## 三品

上品、中品、下品建為 3 個 `herb_grade`，以既有 generic `classified_as` 連接。但只對 V1 明確講授的 12 味建立關係：上品人參、大棗、黃耆、甘草；中品桂枝、麻黃、白朮、乾薑；下品大黃、附子、芒硝、半夏。這是本站古典研讀結構，不等同現代毒性或安全等級。由於傳本與名物對應存在版本差異，本輪沒有把三品擴張到其餘藥材。

## Provenance

來源分為：古典原文整理、本站 V1 編輯課程、香港浸會大學現代規範化參考、結構化衍生。沒有可直接定位的倪海廈本草講授材料，因此未新增 `nihaixia` 主張。Entity sourceIds 表示條目參考範圍；每一條性、味、歸經、品級或經典出處仍由 relation sourceIds 回答「誰支持這一主張」。

## 頁面、搜尋與圖譜

單一 Herb 頁聚合性味、歸經、品級、經典、所有包含它的方劑、延伸課程、局部圖與逐條證據。搜尋索引納入藥性、藥味、臟腑、品級、方劑與經典相鄰節點，繁簡與別名仍指向單一 Herb 結果。

Local Graph 不加入視覺專用 edge。甘草 26 個直接鄰居、桂枝 21；圖維持 18 鄰居上限並顯示省略數，完整文字關係保留。藥性、藥味、歸經排序優先於大量方劑，使高連結藥材仍能呈現本草屬性。

## 安全與延後本體

不提供個人推薦、症狀到藥材、劑量、替代、炮製操作、妊娠、交互作用或毒性結論。缺少警示不代表安全。功效／主治暫以短篇課程文字呈現，沒有建立 action ontology。

完整植物物種、藥用部位、炮製、劑型、毒性、禁忌、現代藥理、完整三品考證及批次匯入均延後。Schema 已能確定性承載性、味、歸經、品級與來源，但開始大量匯入前仍需先定義名物消歧、逐藥來源 locator、傳本版本與衝突報告格式。

## Freeze 判斷

共同 Entity／Relation／Source 欄位經易經、八字、河洛、309 穴、傷寒、金匱與本草壓力測試後已相當穩定。1.5.0 可進入 Knowledge Model V1 freeze planning；但本草 deterministic ingestion 只能進入管線設計階段，不能直接批量發布，因名物、炮製與版本衝突仍需專用匯入層處理。
